# Architecture Decision Log

Format: `D-###` · date · status · decision · rationale · consequences. Append-only; supersede, don't edit.

- **D-001 · 2026-09-24 · accepted · Tauri 2 over Electron/.NET/Godot.** Native Windows binary with a small footprint, WebView2, MSI/NSIS bundling, Rust for heavy data work (JSONL streaming, SQLite). Matches William's StackAssembler stack. Consequence: Rust + MSVC Build Tools required on the dev box (setup script installs).
- **D-002 · 2026-09-24 · accepted · React 19 + TypeScript + Vite frontend.** William's toolchain; largest ecosystem for the UI layer.
- **D-003 · 2026-09-24 · accepted · Framework-free `core/` module.** All parsing/detection/trajectory logic is pure TS with unit tests; UI and Tauri are adapters. Consequence: core is reusable by StackAssembler or a CLI later.
- **D-004 · 2026-09-24 · accepted · Scryfall bulk JSONL → local SQLite, live API only for singles/images.** Offline-first, respects Scryfall's rate limits and bulk guidance. Note: Scryfall bulk moved to JSONL.gz; oracle tags now ship as bulk.
- **D-005 · 2026-09-24 · accepted · Combos are confirmed against Commander Spellbook, not invented.** Local patterns detect *shapes*; Spellbook variants (zoneLocations + step descriptions) supply the concrete, community-verified lines. Manual combos allowed only when the user marks them.
- **D-006 · 2026-09-24 · proposed · Board renderer = PixiJS 8 under a React HUD.** To be confirmed by the Phase 1 spike against SVG + Framer Motion; decide on measured fps with 150 sprites + 40 arrows. Whichever wins, arrows must be crisp at 2× DPI.
- **D-007 · 2026-09-24 · accepted · Opponent "tracks" are static timelines, never a rules engine or AI.** Keeps scope honest; StackAssembler owns simulation.
- **D-008 · 2026-09-24 · accepted · Detection rationale is mandatory.** Every StrategyMatch stores which tag/regex/Spellbook id fired; the UI can always show "why". Prevents confident nonsense.
- **D-009 · 2026-09-24 · accepted · SQLite is owned by Rust (`rusqlite`, bundled, FTS5); the frontend reads through one read-only `db_query(sql, params)` command and writes only through typed Rust commands.** Supersedes the `tauri-plugin-sql` wording in D-004 / ARCHITECTURE. Rationale: one SQLite build (plugin-sql uses sqlx and would drag in a second `libsqlite3-sys`), FTS5 guaranteed, the streaming importer needs Rust anyway, and the SQL strings in `app/src/data/` run unchanged under Node's built-in `node:sqlite` in Vitest against the real imported DB. Consequence: `src/data` owns SQL, `src/bridge` only adapts `invoke`; the read connection is opened `SQLITE_OPEN_READ_ONLY` + `query_only`.
- **D-010 · 2026-09-24 · accepted · Name resolution runs in memory in `core/resolve` (NameIndex built from a `{oracle_id, name, layout}` projection, ≈3.8 MB for 38.7k cards), not via SQL LIKE/FTS.** Exact → face → punctuation-insensitive → trigram + Levenshtein fuzzy, thresholds in code; both TS and Rust normalizers are checked against one golden file. FTS5 (`cards_fts`, unicode61 remove_diacritics 2) is kept for UI autocomplete only. Consequence: resolution is unit-testable without a DB and costs ~0.1 ms per name.
- **D-011 · 2026-09-24 · accepted · Commander Spellbook bulk is imported by a streaming serde visitor and only `status == "OK"` variants are stored, as a trimmed JSON projection.** Measured 2026-09-24: `variants.json.gz` is **664 MB** compressed (KNOWLEDGE_INDEX said ~28 MB; wrong). Consequence: first-run download is dominated by this file; the UI must show its size up front and allow "skip combos for now" (Q-013).
- **D-011a · 2026-09-24 · correction to D-011.** The 664 MB figure is the *inflated* size: Windows PowerShell's `Invoke-WebRequest` honoured `Content-Encoding: gzip` and wrote plain JSON under the `.gz` name. The importer now sniffs the gzip magic bytes and accepts either form; the true compressed size will be recorded by the Rust downloader (`download.rs` keeps bytes as served). Q-013 stands: hundreds of MB inflated is still the largest first-run cost.
- **D-006 · 2026-09-24 · resolved (supersedes the proposed entry above) · Board renderer = React DOM + SVG with Motion; PixiJS not adopted.** Spike `app/spike.html` (`app/src/spike/`), measured inside Tauri's WebView2 (the real target), 1440×900, 10 s windows after 1.5 s warm-up, dev box: NVIDIA GeForce RTX 5070 · 13th Gen Intel(R) Core(TM) i5-13600K.

  | scene | sprites / arrows | render DPR | fps | frame p99 / max ms | `update()` p50 / p95 ms |
  |---|---|---|---|---|---|
  | PixiJS 8 (WebGL) | 150 / 40 | 1 | 60 | 16.8 / 16.9 | 1.0 / 1.2 |
  | SVG + Motion | 150 / 40 | 1 | 60 | 16.8 / 16.9 | 0.2 / 0.3 |
  | PixiJS 8 (WebGL) | 600 / 160 | 2 | 60 | 16.8 / 16.9 | 3.0 / 3.3 |
  | SVG + Motion | 600 / 160 | 2 (CSS-scale emulated) | 60 | 16.8 / 17.5 | 0.5 / 0.7 |
  | PixiJS 8 (WebGL) | 1500 / 400 | 2 | 60 | 16.8 / 16.9 | 7.1 / 8.1 |
  | SVG + Motion | 1500 / 400 | 2 (CSS-scale emulated) | 59.8 | 16.8 / 33.4 | 1.1 / 1.6 |

  Both candidates clear the acceptance bar (150 sprites + 40 live arrows at 60 fps, DPR 2) with a 10× margin, so throughput does not decide it. What does: (1) crispness — `<img>` art crops and SVG strokes are resolution-independent, no texture-resolution bookkeeping; (2) native text, hover, hit-testing, keyboard focus and screen-reader labels on the cards and zones (UI_UX_GUIDELINES accessibility gate) come free with DOM, and would need a parallel DOM under a canvas; (3) `prefers-reduced-motion` and Motion's WAAPI transforms run on the compositor; (4) Playwright can query the board. Pixi's live-arrow geometry rebuild is also the pricier scripting path (7 ms at 10×). Consequences: `app/src/board/` is React components + one SVG overlay for arrows/pulses; `motion` is a runtime dependency; `pixi.js` stays a devDependency for the spike only. Caveat: measured on one desktop with a discrete RTX 5070 — far above the "average Windows laptop" in the brief — so the 10× margin is an upper bound; re-measure on integrated graphics in Phase 4 before v1.0, and Pixi remains the escape hatch if particles or thousands of objects ever appear.
